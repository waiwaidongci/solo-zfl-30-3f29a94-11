# 水下考古多设备时钟校准台

为水下考古数据员准备的**完全离线**时钟校准工具：登记相机、潜水表、声呐等设备的本地钟面时间，
用成对“锚点”（同一瞬间两台设备的读数）建立分段线性映射，在设备图上自动枚举多条换算路径，
全部路径结果一致后才允许发布为不可变版本。

## 使用方式

直接双击打开 `index.html`（`file://` 即可，无需联网、无需构建、无外部依赖）。
所有数据保存在浏览器 `localStorage`，刷新不丢失。

工作流程：

1. **设备登记** — 添加相机 / 潜水表 / 声呐（或其他设备），可改名、可删除。
2. **成对时间锚点** — 录入同一瞬间两设备的本地读数，格式严格为 `HH:MM:SS`，毫秒可选且**必须恰好三位** `.fff`。
3. **重新校准** — 点击右上角按钮执行全部校验，页面显示：
   - 状态徽章（通过 / 已编辑失效 / 未通过）；
   - 每对设备的可用路径数、共同覆盖区间、多路径最大偏差；
   - 冲突来源：错误码、分歧时刻、分歧的两条具体路径、相关锚点“定位”按钮（锚点行标红）。
4. **跨设备换算** — 选源/目标设备与时间，显示换算结果和实际经过的路径。
5. **发布版本** — 校准通过后发布；版本为数据快照，之后可随时在“使用版本”中选用旧版本换算。

## 校验与拒绝规则

| 规则 | 含义 | 错误码 |
| --- | --- | --- |
| 时间格式严格 | 仅接受 `HH:MM:SS[.fff]`；缺秒、时分秒越界（24/60/60）、一位/四位毫秒、逗号小数、非两位补零等混合写法在登记与换算两处均被拒绝，字段下方给出具体原因 | `TIME_MISSING_SECONDS` / `TIME_RANGE` / `TIME_FORMAT` / `BAD_TIME` |
| 锚点严格递增 | 同一设备对内，两台设备的钟面读数都必须随锚点严格增加（倒退即拒） | `ORDER_ANCHORS` |
| 每段漂移 ≤ 5 秒/小时 | 相邻锚点间采用对称漂移率 `|ln(ΔtB/ΔtA)|·3600 ≤ 5`，锚点反向录入结论不变 | `DRIFT_SEGMENT` |
| 路径连通 | 设备图必须连通；链式路径的覆盖区间沿路径取交，不相交即拒 | `PATH_BROKEN` |
| 禁止越界外推 | 换算时刻必须落在该路径的共同覆盖区间内（单锚点边只在锚点时刻有效） | `PATH_BROKEN` |
| 多路径一致 ≤ 1 秒 | 同一设备对的所有独立路径，在共同覆盖区间内逐 30 秒采样，结果差 ≤ 1 秒 | `PATH_CONFLICT` |

- **编辑失效**：增删改设备或锚点后，草稿状态立即变为“已编辑 · 结果失效”，换算与发布立刻不可用；
  重新校准通过后恢复。
- **失败不改变已发布版本**：校准失败、发布被拒均不产生新版本；已发布版本是不可变快照，
  草稿改动后旧版本照常换算。
- **同一版本并发发布只成功一次**：发布为异步操作，进入即占锁；`Promise.all` 并发或快速连点时，
  仅首个请求成功，其余返回 `PUBLISH_BUSY`；同内容重复发布返回 `ALREADY_PUBLISHED`。
- **旧数据兼容**：旧潜水记录应用的 `zfl30Marks` 数据原样保留，页面底部只读展示，不参与校准。

## 文件结构

```
index.html              页面
css/styles.css          样式
js/timeutil.js          HH:MM:SS[.fff] 解析/格式化

playwright.config.js
```

## 自动化测试（真实浏览器）

```bash
npm install
npx playwright install chromium
npm test
```

覆盖场景（Chromium headless 实测）：

- 三角闭合多设备换算、分段线性插值（跨段斜率不同）、反向路径换算；
- 漂移超限 / 恰好 5 秒每小时边界、锚点非严格递增、孤立设备断链；
- 链式路径覆盖区间不相交拒绝、部分重叠时区间外越界拒绝；
- 严格时间输入：合法值与三位毫秒换算、缺秒/越界/混合格式三类非法输入在锚点登记与换算两处均被拒绝并显示明确错误、字段级内联报错实时清除；
- 历史脏数据中的非法锚点：重校失败、草稿换算拒绝、旧版本仍可用，刷新后结论不变、坏数据不丢失；
- 矛盾环路（30 秒分歧）报错含双路径与锚点来源；失败后已发布版本不变、旧版仍可换算；
- 编辑锚点后结果立即失效（换算被拒 `STALE`）、重校拒绝、还原后恢复、全程无新版本；
- 同一版本 5 路并发发布恰好 1 次成功、UI 连点同样只产生一个版本；
- 刷新持久化、旧 `zfl30Marks` 保留只读、断网可用、`file://` 直接打开可用。

> 在无 root 的 Debian/Ubuntu 容器中若 Chromium 缺系统库（如 `libnspr4.so`），
> 运行 `tests/install-local-libs.sh` 可把依赖库下载解压到 `/tmp/chromelibs`；
> `playwright.config.js` 检测到该目录后会自动注入 `LD_LIBRARY_PATH`。
